## 1. 왜 이 앱인가 (v6 요약)

### 1.1 현황 [확인됨]
- 한우 농장 72,389곳 중 HACCP 인증은 1,835곳(**2.5%**)으로 다섯 축종 중 가장 낮습니다. 50마리 이상 농장만 분모로 잡아도 최대 8.9%입니다.
- 농장 HACCP 인증 6,294건 중 스마트HACCP 등록은 **0건**입니다.
- 한·육우 농장의 72.6%가 50마리 미만이고, 축산 농가 경영주의 63%가 60세 이상입니다(2020년, 축산 농가 전체 기준).

### 1.2 원인 세 가지 [확인됨]
1. **구조**: 농장 HACCP은 자율입니다. 인증을 받아도 등급 판정 기준에는 인증 항목이 없어 소 값이 오르지 않습니다.
2. **설계**: 스마트HACCP은 온도·금속 검출처럼 센서로 재는 항목이 중심입니다(중요관리점의 90.3%). 농장의 핵심 항목인 휴약기간은 센서가 아니라 **약 기록과 소 번호를 대조**해야 확인됩니다.
3. **지원**: 정부 로드맵에는 농장이 들어 있었지만 실제 사업은 도축장·집유장만 대상으로 했습니다. 컨설팅 예산도 5년 새 64% 줄었습니다.

### 1.3 농장주 입장의 돈 문제 [확인됨]
- 휴약기간을 놓치면: 기준을 넘은 고기는 전량 폐기되고, 100만 원 이하 과태료가 나오고(수의사 처방에 따른 사용은 예외), 6개월 동안 출하 때마다 검사를 받습니다.
- 여러 번 아팠던 소는 도체중이 가볍습니다(해외 연구: 3번 이상 치료한 소 −39.6kg).
- 언제 팔지가 실제 고민입니다. 거세우는 평균 31.6개월에 출하되지만, 1++ 비중은 35개월에서 가장 높습니다(43.9%). 반대로 일찍 팔면 사료비가 줄어듭니다.

### 1.4 이미 있는 것 [확인됨] — 새로 만들지 않고 연결한다
| 이미 있는 것 | 앱에서 쓰는 방법 |
|---|---|
| **수의사처방관리시스템(전자처방)**: 처방대상 약은 2020년 2월부터 전자처방 의무. 처방전에 농장명, 동물 종류, 약 성분, 용량·용법, 처방일수, 판매 수량이 적힘 | 처방이 나오면 앱으로 가져와 "약 기록 확인" 알림을 띄움 |
| **약 판매기록**: 항생제·호르몬제·구충제 등을 팔면 판매처가 판매일, 제품명, 수량, 용도, 구매자를 기록하고 보존해야 함 | 판매처가 전산으로 보내 주면 처방 없이 산 약도 잡음 |
| **축사로**(국립축산과학원, 한우 농장 HACCP 기록 프로그램): 약품 구매·사용, 수의사 처방 기록 칸이 있고 이력제 정보를 자동으로 불러옴 | 앱에서 확인한 기록을 축사로 장부로 보냄(새 장부를 만들지 않음) |
| **축산물이력제**: 소마다 이력번호, 출생일, 성별, 이동, 도축, 등급 정보. 출하하면 농장경영자가 신고해야 함 | 소 목록과 기본 정보, 도축 후 등급 결과를 가져옴. 출하 신고 전에 휴약기간 경고를 띄움 |
| **축산물원패스**(축산물품질평가원): 등급판정 결과 조회 | 도축 결과 화면의 연결 대상 후보 |

### 1.5 빈틈 [확인됨] — 앱이 메워야 할 곳
- 처방전에 소 이력번호는 필수가 아닙니다. 같은 축사 소들은 한 처방전으로 처방할 수 있습니다. → **"몇 번 소에 쓰셨나요?" 한 번 선택**이 필요합니다.
- 약국은 주사용 항생제 등을 뺀 처방대상 약을 처방전 없이 팔 수 있습니다. → 전자처방만으로는 빠지는 기록이 있어 **판매기록 연결**도 필요합니다.
- 판매기록은 서식이나 전산 제출 규정이 없고 농장식별번호 항목도 없습니다. → 시범에서는 참여 판매처가 자율로 보내고, 확산할 때 규칙 개정을 검토합니다.
- 휴약기간이 남았다고 출하를 **막을 법적 근거는 없습니다.** → 앱은 **경고만** 합니다.

## 2. 사용자

### 2.1 주 사용자 (가상 인물) [가상]
**박영수 씨, 67세, 전라남도, 거세한우 비육 62마리 (농장주)**
- 아내와 둘이 농장을 운영합니다. 자녀는 도시에 살고 가끔 전화로 도와줍니다.
- 휴대폰은 전화, 문자, 카카오톡, 유튜브를 씁니다. 앱 설치는 자녀에게 부탁합니다.
- 약은 읍내 동물약품 판매처에서 사고, 큰 병은 단골 수의사를 부릅니다.
- 약을 쓰면 달력이나 공책에 적는데 자주 빠뜨립니다. 출하 전에는 기억에 의존합니다.
- 가장 신경 쓰는 것: 소 값(등급), 사료값, 병 걸린 소.
- 하기 싫은 것: 긴 글 읽기, 작은 글씨, 여러 번 눌러야 하는 화면, 회원가입.

> 참고 [확인됨]: 50~100마리 한·육우 농장은 12,461곳(2026년 6월)입니다. 박영수 씨 같은 농가가 첫 확산 대상입니다.

### 2.2 함께 쓰는 사람
| 사람 | 앱에서 하는 일 | 프로토타입에서 |
|---|---|---|
| 가족(아내, 자녀) | 같은 농장 계정으로 소 선택·확인을 대신 해 줌 | 가족 초대 화면만 보여 줌 |
| 수의사 | 처방 발급(기존 전자처방), 앱에서 "휴약 남은 소 출하 상담" 전화를 받음 | 가상 처방 데이터 |
| 약 판매처 | 판매기록을 전산으로 보냄 | 가상 판매 데이터 |
| 한국식품안전관리인증원 심사원 | 농장 HACCP 심사 때 앱이 만든 장부를 확인 | 장부 내보내기(PDF)까지만 |

## 3. 핵심 흐름 (한 번의 약 사용이 출하까지 가는 길)

```
[수의사 전자처방]  또는  [약 판매처 판매기록]
          │  (농가가 동의한 경우에만)
          ▼
① 앱 알림: "항생제 ○○ 1병을 사셨습니다. 어느 소에 쓰셨나요?"
          ▼
② 소 선택 (축사 칸별 목록에서 귀표 뒷번호를 누름) + 투약일 선택
          ▼
③ 휴약 종료 시각 자동 계산 → 소 상태가 "휴약 중 D-7"로 바뀜
          ▼
④ HACCP 약품 사용 기록 자동 작성 → 축사로 장부로 전송
          ▼
⑤ 출하 준비: 출하할 소를 고르면 휴약기간 자동 점검
     ├ 모두 끝남 → "출하해도 됩니다" + 출하 전 확인 기록 자동 작성
     └ 남은 소 있음 → 경고(막지 않음) + 수의사 전화 버튼
          ▼
⑥ 도축 후: 이력제에서 등급 결과를 받아 소 기록에 붙임
          ▼
⑦ 쌓인 기록(치료 횟수, 월령, 혈통, 등급 결과)으로 다음 소의 출하 판단 정보 개선
```

- ①~⑤가 **A(부담 제거)**, ⑥~⑦이 **B(돈이 되는 정보)** 입니다.
- 농장주가 직접 하는 일은 **②(소 선택)**와 **⑤(출하할 소 고르기)** 두 가지뿐입니다.

## 5. 화면 설계

### 5.0 공통 원칙 (60대 이상 사용자 기준)
- 글자는 기본 18pt 이상, 핵심 숫자는 28pt 이상. 한 화면의 버튼은 3개 이하.
- 색만으로 상태를 구분하지 않습니다. **초록 "출하 가능" / 주황 "휴약 중 D-7" / 빨강 "출하 주의"** 처럼 글자를 함께 씁니다.
- 소는 **귀표 뒷 4자리**를 크게 보여 줍니다(예: `0352`). 12자리 이력번호는 작게 아래에 둡니다.
- 전문 용어는 처음 나올 때 풀어 씁니다. 예: "휴약기간(약 성분이 빠질 때까지 출하하지 않고 기다리는 기간)".
- 모든 판단 화면에는 **"왜 이렇게 나왔나요?"** 버튼을 둡니다.
- 되돌리기가 항상 가능해야 합니다. 잘못 고른 소는 7일 안에 고칠 수 있습니다 [가정].

- 마지막 투약 시각 + 휴약일수 × 24시간. 예: 금요일 오전 9시 마지막 투약, 휴약 5일 → 다음 주 수요일 오전 9시 이후 출하.
- 투약 시각을 모르면 그날 23시 59분으로 잡아 안전한 쪽으로 계산합니다 [가정].
- 한 소에 여러 약을 썼으면 가장 늦게 끝나는 날짜를 씁니다.
- 같은 성분이라도 제조사마다 휴약기간이 다를 수 있으므로 **제품 단위**로 휴약기간을 저장합니다 [확인됨].

### S5. 출하 판단 (B축의 핵심 화면)
```
┌────────────────────────────┐
│ 0352번 소, 언제 팔까요?     │

├────────────────────────────┤
```

- **모든 숫자는 [가상]**입니다. 프로토타입에서는 아래 "모의 예측 규칙"으로 만든 값을 보여 주고, 화면 위에 "설명용"임을 적습니다.

- "왜 이렇게 나왔나요?"에서는 영향을 준 요인을 쉬운 말로 보여 줍니다. 예: "월령 31개월(가장 높은 시기보다 4개월 이름)", "최근 6개월 치료 1회", "아비 소 계통".
- 사료비 계산에 쓰는 하루 사료량과 사료 단가는 **농장주가 설정에서 넣는 값**입니다. 기본값은 [가정]으로 둡니다.
- 휴약기간이 남은 소는 "지금" 줄에 출하 불가 표시를 붙입니다. A와 B가 한 화면에서 만납니다.

**② 외부 연계 — 기관별로 확인한 경로**
| 출처 | 확인된 경로 | 방법 |
|---|---|---|

### 6.2 프로토타입의 모의 예측 규칙 [가상 — 발표 때 반드시 "설명용"이라고 밝힘]
- 월령별 기본 1++ 확률 곡선을 가정합니다. 예를 들어 35개월 근처에서 가장 높고, 앞뒤로 낮아지는 모양입니다. 모양의 근거는 "1++ 비중이 35개월에 가장 높았다"는 통계 기사입니다 [확인됨]. 구체적인 퍼센트는 [가상]입니다.
- 최근 6개월 치료 횟수만큼 확률을 조금씩 낮춥니다(가정한 보정값). 해외 연구에서 치료가 잦을수록 도체중과 상위 등급 비율이 낮았다는 방향만 따릅니다 [확인됨: 방향].
- 추가 사료비 = 하루 급여량 × 사료 단가 × 추가 일수 (농장주 입력값).
- **실제 모델은 시범 사업 데이터로 학습합니다.** 핵심 검증 질문: "치료 기록을 넣으면 예측이 나아지는가?" [가정]

### 6.3 프로토타입 시연용 데이터 준비물
1. 가상 농장 1곳, 소 62마리(3~6번 칸, 월령 20~34개월 분포)
2. 약 제품 표 10개: **실제 제품명을 쓰지 않고** "항생제 A", "구충제 B"처럼 둡니다. 휴약기간 숫자는 실제 범위에서 고르되 [가정]으로 표시합니다
3. 가상 처방 3건, 가상 판매 2건 (시연 시나리오와 맞춤)
4. 가상 도축 결과 5건 (예측 대비 실제 비교용)

## 10. 프로토타입 만드는 방법

### 10.1 방식 비교
| 방식 | 장점 | 단점 |
|---|---|---|
| **모바일 웹앱(PWA)** — 휴대폰 브라우저에서 열고 홈 화면에 앱처럼 설치 | 링크 하나로 심사위원·조원 누구나 열어 봄. 앱 스토어 등록 불필요. 기존에 만든 HTML 대시보드 경험을 살릴 수 있음 | 휴대폰 알림·문자 연동은 흉내만 가능 |
| Expo(React Native) | 진짜 앱처럼 동작, 휴대폰 알림 가능 | 설치 과정(Expo Go)이 필요, 개발 부담이 큼 |
| Figma 클릭 목업 | 가장 빠름 | 계산(휴약 종료일, 예측)이 실제로 돌지 않음 |

**추천: 모바일 웹앱(PWA)**
- 발표장에서 휴대폰 화면을 그대로 띄우기 쉽고, 기획서에 QR 코드를 넣어 심사위원이 직접 눌러 볼 수 있습니다.
- 휴약 종료 계산과 모의 예측이 실제로 돌아가므로 "진짜 된다"는 인상을 줍니다.
- 알림은 앱 안의 "가상 알림 보내기" 버튼으로 시연합니다.
- 데이터는 가상 JSON 파일로 두고 서버 없이 동작하게 합니다. 휴대폰 안에만 저장합니다.

### 10.2 만드는 순서
| 단계 | 내용 | 끝났다고 보는 기준 |
|---|---|---|
| 1 | 가상 데이터 만들기(농장, 소 62마리, 약 제품 10개, 처방·판매·도축 결과) | JSON 파일 완성, 시연 시나리오와 맞음 |
| 2 | 휴약 계산 규칙 구현과 검사 | 안내문의 예시(금요일 9시 + 5일 → 수요일 9시)를 포함한 검사 통과 |
| 3 | 필수 화면 S1·S2·S3·S4 | 약 알림 → 소 선택 → 상태 변화가 이어짐 |
| 4 | S6 출하 준비, S8 장부(PDF) | 경고 흐름과 장부 내보내기 동작 |
| 5 | S5 출하 판단(모의 규칙), S0 동의 | 시연 시나리오 1~7을 끊김 없이 진행 |
| 6 | 권장 기능(S7, 큰 글씨, 가족 초대) | 시간 남으면 |
| 7 | 60대 이상 3명에게 실제로 써 보게 하기 | "도움 없이 S2를 끝냈는가" 기록 [가정: 섭외 필요] |

## 12. 결정이 필요한 것 (조원 논의)

1. **앱 이름**: "한우 출하노트"로 갈지
2. **프로토타입 방식**: 모바일 웹앱으로 갈지(추천), Expo로 갈지
3. **범위**: 판매처 화면(F15)과 심사원 화면(F16)을 기획서 그림으로만 둘지
4. **문자 대안(F11)**: 시연에 넣을지
5. **사용성 시험**: 60대 이상 농장주나 주변 어르신을 섭외할 수 있는지
6. **공모전 제출 양식**: 프로토타입 링크나 영상 제출이 허용되는지. 아직 확인하지 못했습니다

## 13. 아직 확인하지 못한 사실 (v6에서 이어짐)

1. 전자처방과 판매기록을 축사로(또는 이 앱)로 보낼 수 있는지 — 해결 A의 실현 가능성이 여기에 달려 있습니다
2. 제품별 휴약기간을 기계가 읽을 수 있는 공개 데이터가 있는지 — 없으면 제품 표를 직접 만들어야 합니다
3. 농장 HACCP 기록 양식의 정확한 항목 — S8 장부를 맞추려면 필요합니다
4. 이력제 출하 신고 화면에 경고를 붙일 수 있는지
5. HACCP 인증 농장이 받는 정책 가점 등 다른 우대가 있는지

## 용어 풀이
| 용어 | 뜻 |
|---|---|
| HACCP(해썹) | 위험 요소를 미리 찾아 중점적으로 관리하는 식품·축산물 위생 관리 기준 |
| 스마트HACCP | HACCP 기록을 기계와 전산으로 자동으로 남기는 방식 |
| 중요관리점 | 위험을 막기 위해 반드시 지켜야 하는 핵심 관리 항목 |
| 휴약기간 | 약을 쓴 뒤 고기에 약 성분이 남지 않도록 출하하지 않고 기다리는 기간 |
| 축산물이력제 | 소 한 마리마다 출생·이동·도축·등급을 기록하고 조회하는 제도 |
| 축사로 | 국립축산과학원이 운영하는 한우 농장 HACCP 기록·개체 관리 프로그램 |
| 전자처방 | 수의사가 처방대상 동물약의 처방전을 수의사처방관리시스템으로 발급하는 것 |
| 모바일 웹앱(PWA) | 휴대폰 브라우저에서 열리고 홈 화면에 앱처럼 설치할 수 있는 웹 페이지 |
| 공개 API | 기관이 공개한 데이터를 프로그램이 자동으로 받아 갈 수 있게 열어 둔 연결 창구 |
